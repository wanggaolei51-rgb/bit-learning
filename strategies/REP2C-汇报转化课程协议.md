# REP2C 汇报转化课程协议
# Report-to-Course Transformation Protocol

> 版本: v1.0 | 日期: 2026-10-11 | 状态: **待用户审定后生效**
> 依据策略: C5 v2.1 / BIT v1.2 / RCO v1.0 / M2 v2.4 / BIV v2.2
> 起草: 主 agent 框架 + rep2c-vocab-architect（模块一/二/三）+ rep2c-scene-architect（模块四/五/六）

---

## 零、总则

### 0.1 目标
将用户每周/每月的工作汇报（周汇报、月汇报）转化为 LEO-BIR 平台的 C 课程，
使学习内容与实际工作表达直接对应——**学了就能用，用前已经学**。

### 0.2 输入规格
| 项目 | 规格 |
|---|---|
| 输入材料 | 用户提交的周汇报/月汇报全文（中文为主，可含印尼语片段） |
| 提交频率 | 周汇报：每周一次；月汇报：每月一次 |
| 汇报场景 | 项目管理 / 商务 / 冶炼工业园区运营 |

### 0.3 输出规格
| 产出物 | 格式 | 去向 |
|---|---|---|
| BIT 词条集 | BIT 定稿 md（九字段体例） | bitVocabDB + vocabDB |
| 场景对话集 | C5 规则D 格式（3场景×10-20句/话题） | topic 数据 → index.html |
| 问答对库 | 12-15 组（配比 4-4-3-2） | 课时测试题源（C5 规则E） |
| 勘误对账表 | A3 三方逐词映射表 | RCO 审计附件 |
| 课程数据 JS | dailynote / topic 数据 JS | index.html |

## 一、转化总流程（六阶段）

```
阶段0  REP 接收
  └─ 用户提交周/月汇报全文
       ↓
阶段1  REP 解析【词汇提取】→ 模块一
  └─ 识别核心词汇、词元清洗（去重+大写归一）、六分类、P0-P2定级
  └─ 产出：REP词元表（附汇报原文出处）+ 对账基线
       ↓
阶段2  BIT 词条化 → 模块二
  └─ 八步流水线：登记→清洗→查重→词形归位→九字段→BIO→RCO A3→落盘
  └─ 产出：BIT 定稿 md
       ↓
阶段3  句型与场景提取 → 模块四 + 模块五
  └─ 五段切片→句型模板化→场景对话组装
  └─ 产出：句型模板表 + 3场景对话稿
       ↓
阶段4  扩展词汇衍生 → 模块三 + 模块六
  └─ 从场景对话/问答反向提取扩展词（≤30%上限）→ 回阶段2补词条
  └─ 产出：扩展词 BIT 词条 + 问答对库（12-15组）
       ↓
阶段5  三审 + 部署（M2 三审机制）
  └─ BIO 审查 → RCO A3 对账 → TSO 执行合并
  └─ M2 部署：check_syntax → deploy-check 8/8 → git push → 线上验证
```

### 1.1 阶段间衔接规则
- 阶段1→2：词元表冻结后才可进入词条化（RCO 对账基准）
- 阶段3→4：场景对话定稿后才可提取扩展词（避免范围蔓延）
- 阶段4→2 回环：扩展词走与原始词完全相同的 BIT 流程，不降低标准
- 阶段5 三审顺序：BIO → RCO → TSO（内容→质量→执行）

### 1.2 时序建议
| 阶段 | 建议耗时 | 说明 |
|---|---|---|
| 阶段0-1 | 汇报提交后 1 天内 | 词汇提取 |
| 阶段2 | 1 天内 | 词条化（>30词须拆 sub-agent） |
| 阶段3 | 1-2 天 | 句型+场景对话 |
| 阶段4 | 0.5 天 | 扩展词衍生+问答对 |
| 阶段5 | 0.5 天 | 三审+部署 |
| **总计** | **3-5 天/期** | 每周/每月滚动执行 |

## 二、质量控制基线

### 2.1 RCO A3 对账（强制）
REP2C 语境下三方定义（显式重定义，不等同于日常笔记任务）：
1. **方一**：用户汇报原始词元（清洗前去重后）
2. **方二**：清洗归位后进入生成的任务词表（含 P0-P2 定级与 A-F 分类标签）
3. **方三**：最终 BIT 词条 word 字段

- 逐词映射，产出对账表：原始词元 → 归位后词根 → 分类 → 优先级 → 最终词条（或落选原因）
- **任何一个原始词元在对账表中无去向说明 = FAIL**，阻断上线

### 2.2 覆盖率指标
| 指标 | 目标 |
|---|---|
| 汇报核心词覆盖率 | 100%（提取的词全部词条化） |
| 词条九字段完整率 | 100%（无空缺字段） |
| 例句语境适配率 | ≥90%（项目管理/商务/冶炼园区语境） |
| 印尼语纯度 | 100%（零方言混入） |
| 场景核心词覆盖 | ≥8/场景，3场景合计 ≥20 |
| 核心词场景复现率 | ≥2（每个核心词出现在 ≥2 个场景） |

### 2.3 词汇量约束（C5）
- 每期转化课程核心词：20-40 词，目标 38-40（C5 精简标准）
- 扩展词 ≤ 原始汇报词数的 30%
- 场景对话中扩展词另行统计，不计入核心词上限

## 四、模块一：汇报词汇提取规则

### 4.1 提取标准（一个词值得学的判定条件）

从汇报原文中扫描全部候选词，**满足以下任意一条即入选**：

| 编号 | 标准 | 判定方法 | 示例 |
|---|---|---|---|
| S1 | 高频复现 | 本期汇报出现 ≥2 次，或近 4 期累计出现 ≥2 次 | anggaran（预算）每期都出现 |
| S2 | 场景刚需 | 删掉该词，汇报核心事实无法完整表达（"支点词"测试） | progress、keterlambatan、K3 |
| S3 | 工作场景高频 | 印尼同事在会议/现场实际使用的口语/书面常用词 | rapat koordinasi（协调会） |
| S4 | 词根生产力 | 可派生 ≥3 个变形（含词缀变化） | kerja → bekerja / pekerjaan / pekerja / dikerjakan |
| S5 | 用户主动标记 | 用户在汇报中用【】、加粗或"这里怎么说"标出的词 | 用户写"达产【】" |

**排除项（即使满足上述标准也不提取）：**

| 编号 | 排除类型 | 原因 | 处置 |
|---|---|---|---|
| X1 | 一次性专名（人名、设备编号、临时会议名） | 无复用价值 | 不建词条 |
| X2 | 中文行政套话对应词（如"高度重视""扎实推进"） | 印尼语职场沟通不这么说话 | 转化为印尼语实际表达（见 5.2 情况 1） |
| X3 | 纯数字本身 | 不是词汇问题 | 但"数字+单位/量级"表达要学（分类 D） |
| X4 | 方言/地方俚语 | 违反印尼语纯度约束 | 替换为标准印尼语（bahasa Indonesia baku），原词记入 note 供识别 |

### 4.2 分类体系（六分类）

每个入选词必须归入且仅归入以下一类，分类决定后续生成时的处理策略：

| 类 | 名称 | 词性特征 | 典型示例 | 生成侧重 |
|---|---|---|---|---|
| A | 业务术语 | 名词/复合名词 | smelter、peleburan、kontraktor、rantai pasok、AMDAL | cn/en 释义精确到行业义项 |
| B | 动作动词 | 动词（含派生） | menyelesaikan、mengalami、melakukan、menunda | forms[] 必须完整（主动/被动/名词化） |
| C | 状态与变化 | 形容词/状态动词/副词 | tertunda、tepat waktu、optimal、signifikan | 反义词字段优先填充 |
| D | 数字与时间表达 | 数词/量词/时间名词 | persen、kuartal、minggu depan、akhir bulan、kali lipat | note 写清搭配格式 |
| E | 逻辑连接 | 连词/介词短语 | berdasarkan、oleh karena itu、meskipun、sehubungan dengan | 例句必须体现句间逻辑 |
| F | 固定搭配 | 动宾/形介/介宾搭配 | melakukan inspeksi、sesuai dengan、terkait dengan | word 字段直接记搭配整体 |

> **分类强制**：词元清单中每条必须带分类标签（A-F），分类标签在 RCO A3 对账时作为检查列。

### 4.3 优先级规则（P0/P1/P2 三级 + 配额控制）

| 优先级 | 条件 | 处理 |
|---|---|---|
| P0（必选） | 满足 S5（用户标记）；**或** 满足 S2 且属于 B/C/E 类 | 直接入选，不受配额挤压 |
| P1（应选） | 满足 S1-S4 中任意两条的 A/D/F 类词 | 参与配额排序 |
| P2（可选） | 仅满足一条标准的词 | P0+P1 不足 20 词时补齐 |

**配额控制（对齐 C5 词汇量约束）：**

1. 每话题总量 20-40 词，**目标 38-40**（C5 精简标准）
2. 若 P0+P1 总数 > 40：按以下顺序排序截取——
   ① 用户标记词（S5）优先；② 复现次数高者优先；③ 类别权重 B > C > E > A > F > D
3. 若 P0+P1 总数 < 20：按 P2 → 模块三反向提取的顺序补齐
4. 被截断的词不丢弃，写入"下期待学清单"，随下一期 REP2C 任务优先重评

## 五、模块二：汇报词汇 → BIT 词条转化规则

### 5.1 完整映射流程（八步流水线）

```
Step 0 词元登记 → Step 1 词元清洗 → Step 2 查重比对 → Step 3 词形归位
→ Step 4 九字段填充 → Step 5 BIO 审查 → Step 6 RCO A3 对账 → Step 7 落盘部署
```

**Step 0：词元登记**
- 从汇报原文逐一照抄候选词，**原样登记不做任何改动**（含大小写、空格、拼写瑕疵），形成《词元登记清单》，一列原文、一列出处（第几段/第几行）

**Step 1：词元清洗**
- 去首尾空格（10/08 前词库曾混入 `' estimasi'` 类脏数据，此步为硬性步骤）
- 大小写归一：全小写为检索键，保留原大写写法的映射记录
- 去重：同一词的多种变形标注为一组（dibahas / membahas / bahas → 组号一致）

**Step 2：查重比对**（与 bitVocabDB 已有词条比对）
- **命中** → 走"复习重收"流程：词条覆盖更新为最新版；若本次汇报例句更贴合语境，替换 examples[] 中最旧的一句；同词覆盖为设计行为，不告警
- **未命中** → 进入 Step 3 新建词条

**Step 3：词形归位**
- 把变形还原为词根词条：dibahas → bahas；sedang dikerjakan → kerja
- **保守原则**：拿不准是否为同一词根的，保留原出现形式，root 字段标 `[待核实]`，禁止编造词根

**Step 4：九字段填充**（BIT V1.0）

| 字段 | 填充规则 |
|---|---|
| word | 词根原形（印尼语标准拼写） |
| cn / en | 释义取**汇报语境义项**；一词多义时只写与本期汇报相关的义项 |
| root | 保守填写；不确定 → `[待核实]` |
| forms[] | **BIT 定稿 md 中必须用表格格式**（BIT 1.2 硬性要求），禁止顿号列表 |
| formsNote | 变形规则一句话（如"meN- 主动 / di- 被动 / peN--an 名词化"） |
| note | 记录该词在汇报中的固定搭配；REP2C 扩展词按 7.2 加标记 |
| synonyms[] | 至少 1 个真正同义词；没有则空数组，禁止编造 |
| antonyms[] | C 类词优先填；确实无反义词则空数组 |
| examples[] | 2-3 句，按 5.3 例句设计规则 |

**Step 5：BIO 审查**
- 印尼语纯度（禁方言）、释义准确性、词根保守性、例句语境合规

**Step 6：RCO A3 词级三方对账**
- 按 2.1 定义逐词映射，产出对账表
- **任何一个原始词元在对账表中无去向说明 = FAIL**，阻断上线

**Step 7：落盘部署**
- 词元量 ≤15：主 session 直接生成；16-30：每 10 词落盘一次；>30：按 M2 v2.4 拆 sub-agent 并行（20 词/批）
- 批次 JSON 落盘 `/tmp/bit_<date>_batch<N>.json`，主 session 只合并编排

### 5.2 特殊情况处理

**情况 1：汇报只有中文、没有印尼语**
1. 以中文词为**语义锚点**，先查 bitVocabDB / vocabDB 反查已有印尼语对应词
2. 词库已有 → 复用该词条，例句换新
3. 词库没有 → 转译为印尼语标准词（KBBI 通用词，禁方言），**双源核对**（两个独立来源一致）后定稿
4. 该词条 note 加标注：`自中文'达产'转译`，保证溯源
5. 例：汇报"达产率 85%"→ 转译 mencapai kapasitas produksi → 词条建在 kapasitas（A 类）上
6. 中文行政套话按 X2 规则转化为印尼语职场真实表达，不直译

**情况 2：缩写处理**

| 缩写类型 | word | root | note | 示例 |
|---|---|---|---|---|
| 国际通用（KPI / HSE / PM / SOP） | 缩写全大写 | 英文全称 | 全称 + 印尼语读法 + 中文功能 | word: KPI, root: key performance indicator |
| 印尼本土（UU / AMDAL / RKAB / IUP） | 缩写全大写 | **印尼语全称** | 全称 + 中文功能说明 | word: AMDAL, root: Analisis Mengenai Dampak Lingkungan |
| 企业/项目内部缩写 | 不建词条 | — | 写入关联词条 note | 园区内部编号 → 记入对应业务词条 note |

- forms 对缩写一律放空数组；同义词放其印尼语全称的普通词形式（如 KPI ↔ indikator kinerja）

**情况 3：专有名词**
- 公司名/机构名/人名/地名：**原则上不建词条**
- **例外**：专名由可学习的通用词构成且高频复现（如 "Kawasan Industri Morowali"）→ 拆出通用词部分建词条（kawasan、industri），专名整体记入 note
- 冶炼工艺专名（RKEF、HPAL）：按"国际通用缩写"处理，note 加一句中文工艺说明

**情况 4：原文印尼语拼写不规范**
- 词元登记照抄原文；word 字段用规范拼写；对账表记录"原文 → 规范"映射列
- 同一不规范拼写出现 ≥2 次：在 note 中提示常见误拼，帮助用户识别

### 5.3 例句设计规则

1. **源自汇报**：例句必须从汇报原文改写，禁止凭空造句。改写幅度 ≤30%——保留原句词汇搭配与句式结构，只替换数字、人名、敏感信息
2. **数量与结构**：每词 2-3 句。≥1 句保留原句骨架（忠实语境）；其余变换人称/时态/语态，刻意展示 forms[] 中的变形
3. **必含目标词**：例句必须含目标词或其变形（RCO WARN 拦截项，红线 R7）
4. **语境优先级**：项目管理/商务/冶炼园区 > 一般商务 > 通用场景。**禁止出现与园区工作无关的生活化例句**
5. **敏感信息处理**：人名 → Pak/Bu 或职务（"Kepala HSE"）；具体金额 → 模糊化（sekitar 150 ribu dolar AS）；具体公司名 → perusahaan kita / perusahaan mitra；内部编号 → 脱敏

## 六、模块三：扩展词汇衍生规则

### 6.1 反向提取标准

当场景对话/问答/测试中出现了汇报原文没有的新词，**同时满足以下三条**才可提取为扩展词：

| 条件 | 判定 |
|---|---|
| E1 复现 | 场景对话/问答中实际出现 ≥2 次 |
| E2 可归 | 能归入六分类（A-F）之一 |
| E3 可联 | 与某原始汇报词存在明确语义关系：同义 / 反义 / 上位 / 下位 / 高频搭配共现 |

**上限约束**：扩展词 ≤ 原始汇报词数的 30%（38 词中 ≤11 个）。超限按"场景复现次数 → 用户问答中主动询问次数"排序截取。

**来源优先级**：场景对话高频新词 > 用户做问答时主动询问的词 > 测试错题涉及的词

### 6.2 扩展词与原始汇报词的关联标记方式

**机器可识别标记（写入 note 字段前缀）**：

```
[REP2C-EXT 同义:anggaran]     ← 与原始词同义
[REP2C-EXT 反义:tepat waktu]  ← 与原始词反义
[REP2C-EXT 搭配:melakukan]    ← 与原始词构成高频搭配
[REP2C-EXT 上位:pekerjaan]    ← 原始词的上位词
[REP2C-EXT 下位:inspeksi]     ← 原始词的下位词
```

**人工可读附表（BIT 定稿 md 附录，随对账表一并交付）**：

| 原始汇报词 | 扩展词 | 关系类型 | 出现场景 | 提取理由 |
|---|---|---|---|---|
| anggaran | bujet | 同义 | 场景2·成本讨论 | 对话中预算与 bujet 交替使用 3 次 |

### 6.3 回流联动机制
1. 扩展词进入 bitVocabDB 后与原生词同等管理，遵守同词覆盖规则
2. 用户后续汇报再出现原始词时，其 REP2C-EXT 扩展词在 BIT 弹窗同义词区一并展示，形成"汇报词 ↔ 扩展词"复习联动
3. 每期 REP2C 任务结束时，扩展词对账附表并入 RCO A3 对账表归档

## 七、模块四：核心句型提取规则

### 7.1 汇报结构五段切片

任何周汇报/月汇报，先按以下五段强制切片（切片是后续一切工作的索引）：

| 段编号 | 段名 | 典型中文标志词 | 必须提取句型数 |
|---|---|---|---|
| P1 | 已完成 | 本周完成、已交付、已投产、已验收 | ≥2 |
| P2 | 进行中 | 正在推进、截至目前、形象进度 | ≥1 |
| P3 | 下步计划 | 下周计划、下月安排、拟启动 | ≥1 |
| P4 | 问题与风险 | 存在问题、风险、滞后、制约因素 | ≥1 |
| P5 | 协调与请求 | 需协调、恳请、申请、建议 | ≥1 |

**规则 7.1.1**：切片后与原文逐段核对，五段各自非空。某段为空时，标记 `P4=空` 并在句型表中登记"本话题无风险段"，禁止跳过（空段也是课程设计信息：说明该话题要教"报喜"句式而非"报忧"句式）。

**规则 7.1.2**：五段映射为汇报课程的教学主线 `完成→进度→计划→风险→请求`，此顺序就是场景对话主体的默认叙事顺序。

### 7.2 句型的印尼语模板化方法（四步流水线）

**第 1 步 · 主干抽取**——从每段中文里挑高频句式，每段 1-2 个，先写成中文骨架：
```
本周完成 {X} 项工作 → 下周计划 {Y} → 需要协调 {Z}
```

**第 2 步 · 印尼语直译**：
```
Minggu ini kami telah menyelesaikan {X} pekerjaan → rencana minggu depan: {Y} → kami memerlukan dukungan {Z}.
```

**第 3 步 · 语序调优**（印尼语商务表达规范）：
- 时间状语前置：`Pada minggu ini, kami telah menyelesaikan...`
- 数字后置用 `sebesar`：`mencapai angka sebesar {X} persen`
- 正式动词优先：`menyampaikan`（汇报）> `bilang`；`mengalami kendala`（遇阻）> `ada masalah`

**第 4 步 · 槽位类型化**：

| 槽位类型 | 标记 | 可替换内容来源 |
|---|---|---|
| 事物槽 | `{item}` | topic.vocab 名词 + BIT 同义词 |
| 动作槽 | `{aktivitas}` | topic.vocab 动词 |
| 数字槽 | `{angka}` | 占位符，不填真实数据（红线 R1） |
| 时间槽 | `{tanggal/periode}` | 固定套语库（见 7.4） |
| 人员/单位槽 | `{unit}` | 部门名、承包商名套语 |

### 7.3 一模板 → 多句扩展机制（纵横两轴）

每个模板必须做两轴扩展，单模板最小产出 6 个句子变体，达不到不准入库。

**横轴 · 槽位替换**：每个槽位从 topic.vocab 及 BIT synonyms 中取 ≥5 个同域替换词

**纵轴 · 时态/语态变体**：同一骨架至少做 2 种时态变体
```
已完成: Minggu ini kami telah menyelesaikan {item}.
进行中: Saat ini kami sedang mengerjakan {item}.
将计划: Minggu depan kami akan menyelesaikan {item}.
```

**扩展公式**：`变体句数 = 槽位替换数 ≥3 × 时态变体数 ≥2 = 每模板 ≥6 句`

**校验 7.3.1**：扩展产出的句子逐句复读，凡读起来不像总经理会说的，删。检验标准：**能否想象在 Morowali 园区会议室里对董事长/政府官员说出口**。

## 八、模块五：场景对话生成规则

### 8.1 汇报场景 → C5 场景对话映射

C5 规则D 要求每话题 3 个场景。四类候选场景按以下决策矩阵选 3：

| 场景类型 | 标志 | 触发条件（看话题语义） | 优先级 |
|---|---|---|---|
| **S-A 向上汇报** | 对董事会/董事长/总部视频会 | 每个话题**必选**（汇报课程主线） | 固定 |
| **S-B1 平级协调** | 跨部门：工程↔生产↔采购↔物流 | 话题含 接口/配套/移交/到货 类语义 | 二选一 |
| **S-B2 下属指导** | 给部门经理布置任务、查进度 | 话题含 执行/班组/节点/验收 类语义 | 二选一 |
| **S-C 外部对接** | 对政府部门/供应商/承包商/社区 | 话题含 许可/合规/采购/物流/劳工 类语义 | 条件选 |

**规则 8.1.1**：每话题 3 场景 = S-A + (S-B1 或 S-B2) + (S-C 若触发，否则 S-B 两选二)。
**规则 8.1.2**：三个场景类型不得重复；话题连续两周出现时，第二次 S-B 必须轮换（B1↔B2）。
**规则 8.1.3**：全部场景人物、职务沿用平台统一设定（总经理 + 董事会 + 部门经理 + 外部单位），保持跨话题连续性。

### 8.2 单场景对话结构设计（开场 → 主体 → 收尾）

每场景 10-20 句（建议落 14-16 句），三段式固定分配：

| 段落 | 句数 | 功能 | 写作要点 |
|---|---|---|---|
| 开场 | 2-4 | 寒暄 + 定调 | 称呼（Bapak/Ibu/Pak/Bu）+ 一句 agenda |
| 主体 | 6-10 | 五段叙事 | 按 7.1.2 主线顺序排话轮；每个话轮 = 汇报人 1-2 句（嵌模板）+ 对方 1 句（追问/确认） |
| 收尾 | 2-3 | 行动项 + 跟进 | 确认 action items、下次汇报时间、礼貌收尾 |

**话轮配比规则**：主体至少 3 个话轮；对方追问中至少 1 个必须是"非善意话轮"（质疑/追问），不能只演顺毛对话——真实汇报一定有质询（此句同时是问答对的钩子来源）。

### 8.3 核心词汇嵌入规则

- **覆盖硬指标**：单场景 ≥8 个 topic.vocab 核心词，3 场景合计 ≥20 个
- **复现硬指标**：每个核心词至少出现在 2 个不同场景中（间隔复现，利于记忆）
- **密度红线**：生词密度 ≤30% 的句子；一句不塞 2 个以上生词
- **BIT 接入**：核心词首次出现处标注 `[BIT: word]`，渲染层走 showBITInfo 四级回退链弹窗
- **自然度要求**：模板句必须揉进对话流，禁止连续 2 句都是模板原句（红线 R8）；模板句之间用口语短句过渡

### 8.4 语言难度控制

对用户水平假设：能用印尼语日常沟通 + 阅读简单公文，但**正式商务汇报句式不熟**。

| 控制项 | 硬约束 |
|---|---|
| 句长 | ≤25 词/句；超过则拆两句 |
| 信息密度 | 一句只承载一个信息点 |
| 时态优先级 | sedang → telah/sudah → akan 梯度出现；虚拟语气禁用 |
| 语态 | 主动 meN- 为主；被动 di- 每场景 ≤3 处 |
| 从句 | `yang` 定语从句可用；`bahwa/ketika` 从句每场景 ≤3 处 |
| 行业黑话 | 每场景新增 ≤2 个，必须给中文注释 |
| 术语规范 | 冶炼园区标准术语（tungku RKEF, ferronikel, AMDAL, K3, smelter），禁自造词 |

**降级通道**：写超难度时，优先删从句、拆长句，**不许删核心词**（核心词覆盖是硬指标，句法复杂度是可调项）。

### 8.5 场景对话片段示例（S-A 向上汇报 · 前 6 句）

> 1. 总经理：Bapak Liu, terima kasih atas waktunya. Hari ini saya akan melaporkan progres pembangunan smelter untuk minggu ini.
> （刘董，感谢您的时间。今天我汇报本周冶炼厂建设进度。）
> 2. 董事长：Silakan, Bapak Zhang. （请讲，张总。）
> 3. 总经理：Pada minggu ini, kami telah menyelesaikan pemasangan pipa utama. [BIT: pemasangan]
> （本周我们已完成主管道安装。）
> 4. 总经理：Progres keseluruhan telah mencapai angka sebesar {angka} persen, sesuai jadwal. [BIT: jadwal]
> （整体进度已达 X%，符合计划。）
> 5. 董事长：Bagaimana dengan uji coba tungku? Apakah sudah sesuai rencana?
> （炉体试运行怎么样？按计划了吗？）← 非善意话轮，钩子 H-01
> 6. 总经理：Uji coba tungku pertama sedang berjalan. Namun kami mengalami kendala teknis di bagian pendingin. [BIT: kendala]
> （一号炉试运行正在进行，但冷却部分遇到技术困难。）

## 九、模块六：问答对设计规则

### 9.1 提问类型预判（4 类）

| 类型ID | 名称 | 上级典型问法（中文） | 预判信号（对话中出现即预埋钩子） |
|---|---|---|---|
| Q-T1 | 进度质疑 | 为什么滞后？什么时候能补上？ | 对话报滞后/风险/变更 |
| Q-T2 | 数据追问 | 这数字怎么来的？口径是什么？ | 对话中出现任何数字 |
| Q-T3 | 风险询问 | 最大风险是什么？对策？ | 对话提及风险/合规/安全 |
| Q-T4 | 资源请求 | 还需要什么支持？什么时候到位？ | 对话提及请求/协调 |

**规则 9.1.1**：每个话题按 **4-4-3-2** 配比产 **13 组**问答对，落在 12-15 区间。超 15 的部分进题库备选池（供 C5 规则E 测试题取材）。

**规则 9.1.2**：问答对问句必须口语化（是"听出来的追问"），不用书面长句。每类至少 2 种问法变体。

### 9.2 标准回答模板（公式化，4 段式）

每类回答统一为 **"态度 → 事实 → 措施 → 承诺"** 四段：

**Q-T1 进度质疑 → REP-ANS-01**
```
态度: Benar, {item} memang tertunda {durasi}. （确实滞后）
事实: Penyebabnya adalah {alasan objektif}. （客观归因，禁推责）
措施: Kami sudah {tindakan 1} dan akan {tindakan 2}. （补救）
承诺: {Item} akan selesai paling lambat pada {tanggal}. （新死线）
```

**Q-T2 数据追问 → REP-ANS-02**
```
口径: Angka {X} dihitung dengan metode {metode}. （怎么算的）
来源: Sumber datanya dari {sumber}. （从哪来）
对比: Dibandingkan {periode} lalu, angkanya {naik/turun} {Y} persen. （对比）
确认: Jika Bapak perlu, kami sertakan detail perhitungannya. （留口供材料）
```

**Q-T3 风险询问 → REP-ANS-03**
```
排序: Risiko utamanya adalah {risiko}. （最大的风险）
影响: Dampaknya pada {area}: {dampak}. （影响面）
措施: Mitigasi kami: {langkah 1}; {langkah 2}. [BIT: mitigasi] （对策）
责任: Penanggung jawabnya {unit}, pemantauan setiap {frekuensi}. （责任人+频率）
```

**Q-T4 资源请求 → REP-ANS-04**
```
需求: Kami memerlukan {sumber daya}. （要什么）
数量: Jumlahnya sekitar {jumlah}. （多少）
用途: Ini untuk {tujuan}. （干什么用）
时限: Idealnya tersedia sebelum {tanggal}. （最晚何时）
```

**规则 9.2.1**：每组问答对给出 1 个标准答（完整四段）+ 2 个精简变体（各 1-2 句，供口语应急）。变体从四段里砍，砍的顺序固定为 对比→确认→责任（先砍次要信息）。

### 9.3 问答对与场景对话的配合机制（三级索引）

1. **对话里埋钩子**：场景对话主体话轮中，对方追问句即钩子，每场景埋 1-2 个，全话题 3-4 个。钩子句末标注 `← H-01` 编号
2. **问答对编号回指**：问答对库每条标 `H-01 → Q-T1 → REP-ANS-01`，形成"场景 ↔ 钩子 ↔ 问答对"三级索引
3. **课程呈现方式**：
   - 场景对话页：钩子处默认折叠"遇到追问怎么答"面板，点开显示对应标准答
   - 测试区（C5 规则E 15 题）：钩子对应的问答对是口语应答题的优先素材池
   - 复习日：整组问答对进 C4_MAP 总结，与场景对话并列回顾

**规则 9.3.1**：任何出现在场景对话里的质疑/追问，问答对库必须有对应条目，禁止"对话里有坑、库里没弹药"。反向也成立：库里的每组问答对，至少在一个场景中找到它的钩子或适用语境，否则移出本话题。
