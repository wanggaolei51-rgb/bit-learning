# M2 管理机制 / M2 Management Protocol

> 版本: 2.4 | 最后更新: 2026-10-08 | 状态: 生效中

---

## 一、时间管理
- **30 秒确认**：收到任务后 30 秒内确认收到并开始执行
- **工期考核**：任务交付前自检完成度，不合格不上交
- **部署复审**：部署后必须线上验证（curl md5 比对 + 日期存在性 + 版本号 badge）

## 二、M2.2 三审机制

每个上线版本必须通过三方独立审核：

| 审核方 | 职责 | 检查项 |
|---|---|---|
| **TSO** | 代码执行 | index.html 修改正确性、语法、部署 |
| **RCO** | 质量审计 | A1 抽样 / A3 词级三方对账 / W1-W2 处置 |
| **BIO** | 内容审查 | 词条准确性、印尼语纯度、例句语境 |

### RCO 审计细则
- **A1 抽样**：随机抽取词条检查准确性
- **A3 词级三方对账**：用户输入词元 vs 最终词条逐词对齐
- **WARN → 修复 → APPROVE**：发现问题先警告，修复后审批
- **同类问题 N 次直报**：同一类问题出现 N 次直接上报指挥官

## 三、部署流程（标准 SOP）

```
修改 index.html → 备份到 /tmp/ → check_syntax.py → deploy-check.sh 8/8
→ git commit + push → GitHub Pages ~70s → curl 线上验证
```

### 硬性检查清单（deploy-check.sh 8项）
1. 当前分支 = main
2. 无未提交更改（或已知）
3. 版本号一致（title / ver badge / changelog）
4. vocabDB 括号平衡
5. topicData 括号平衡
6. topicCalendar 无重复声明
7. topicData 无重复声明
8. vocabDB 无重复声明

## 四、大批量任务并行生成策略（10/8 新增）

### 背景
2026-10-07 22:58，63 词元 BIT 部署任务由主 session 独自处理，多轮 exec 工具调用导致 context 膨胀，模型单次推理超时（>120s），任务中断未完成。10/8 恢复执行时改用 sub-agent 并行方案，全程无超时。

### 规则

| 词元量 | 策略 |
|---|---|
| ≤15 | 主 session 直接生成 |
| 16–30 | 主 session 生成，每 10 词落盘一次 |
| >30 | **必须拆 sub-agent 并行生成** |

### sub-agent 并行规范
1. 按 **20 词/批** 拆分为 N 个 sub-agent（末批可 ≤19）
2. 每个 sub-agent 独立生成 JSON → 写入 `/tmp/bit_<date>_batch<N>.json`
3. 主 session 只做编排：词元清洗 → spawn → 合并 JSON → 部署脚本
4. **批次结果立即落盘**，不留 context
